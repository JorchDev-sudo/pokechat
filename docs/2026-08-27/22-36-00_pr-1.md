# Inicialización de Pokechat: Base de Datos, GraphQL, Repositorios Reactivos y Pipeline de Documentación

## Resumen
Esta actualización establece la base fundamental para el módulo de chat en el proyecto PokeTeams. Se ha diseñado e implementado el esquema inicial de base de datos con Flyway, el esquema de GraphQL (Schema-First) para mensajería y conversaciones, las entidades de dominio y repositorios reactivos integrados con Spring Data R2DBC, y se ha configurado un pipeline automatizado de integración continua (CI) en GitHub Actions para generar documentación técnica de forma automática mediante la API de Gemini.

## Detalle técnico

### Infraestructura de CI/CD y Documentación Automatizada
- **`.github/workflows/generate-docs.yml`**: Se crea un nuevo workflow en GitHub Actions que se dispara cada vez que se cierra y fusiona (merge) de forma exitosa un Pull Request de `develop` a `main`. Este workflow utiliza `google-github-actions/run-gemini-cli@v0.1.22` para recopilar de forma automatizada los commits y el diff, generar la documentación técnica en español y registrar el resultado de forma ordenada bajo `docs/YYYY-MM-DD/HH-MM-SS_pr-XX.md`, actualizando asimismo el índice general `docs/README.md`.

### Configuración de Base de Datos y Migraciones
- **`pom.xml`**: Se agregan las dependencias de Flyway (`flyway-core` y `flyway-database-postgresql`) para posibilitar el control de versiones del esquema de base de datos relacional de PostgreSQL.
- **`src/main/resources/application.yaml`**: Se deshabilita la generación automática de esquemas DDL de Hibernate (`spring.jpa.hibernate.ddl-auto=none`) y se habilita explícitamente el uso de Flyway (`spring.flyway.enabled=true`).
- **`src/main/resources/db/migration/V1__init_chat_schema.sql`**: Define el esquema relacional inicial con PostgreSQL habilitando la extensión `pgcrypto` para generar identificadores UUID de forma aleatoria (`gen_random_uuid()`). Se crean las siguientes tablas e índices:
  - `conversations`: Registro de chats con identificador único y marca de tiempo de creación.
  - `conversation_participants`: Tabla asociativa que conecta cada conversación con los entrenadores correspondientes (`trainer_id`).
  - `messages`: Almacena el identificador del mensaje, emisor, la relación con la conversación, el contenido textual y la fecha de envío.
  - Índices `idx_messages_conversation_sent_at` (búsquedas ordenadas temporalmente de forma descendente en una conversación) y `idx_participants_trainer` (búsqueda eficiente de los participantes).

### Capa de Modelo y Repositorios de Acceso Reactivo
- **`Conversation.java` y `Message.java`**: Entidades de dominio base anotadas con `@Table` y mapeadas para Spring Data. Hacen uso de identificadores `UUID` y marcas de tiempo de tipo `Timestamp` o `timestamptz`.
- **`ConversationRepository.java`**: Interfaz de repositorio reactivo que extiende de `ReactiveCrudRepository` e introduce la firma para encontrar conversaciones de forma reactiva filtradas por participante (`findAllByParticipantId`).
- **`MessageRepository.java`**: Repositorio reactivo que extiende de `ReactiveCrudRepository` e incluye soporte para paginación reactiva (`findAllBy(Pageable pageable)`), permitiendo una recuperación fragmentada y de alto rendimiento de los registros de mensajes.

### Capa de Servicios
- **`ChatService.java` y `MessagePublisher.java`**: Se agregan las clases base como andamiaje para la futura implementación de la lógica de negocio técnica de envíos y la distribución de mensajes en tiempo real.

- `org.flywaydb:flyway-database-postgresql`

### Definición del Esquema GraphQL (`src/main/resources/graphql/schema.graphqls`)
Se define la especificación del esquema GraphQL inicial que expone las operaciones de consulta, modificación y suscripción reactiva:

- **Tipos de Datos**:
  - `scalar DateTime`: Tipo escalar personalizado para marcas de tiempo.
  - `type Conversation`: Representación del chat que contiene el ID, la lista de participantes (`participantIds`) y la fecha de creación (`createdAt`).
  - `type Message`: Estructura del mensaje individual que incluye ID del mensaje, ID de conversación, ID del emisor (`senderId`), contenido de texto y fecha de envío (`sentAt`).

- **Queries (Consultas)**:
  - `findConversations: [Conversation!]!`: Consulta general de las conversaciones del usuario actual.
  - `findMessages(conversationId: ID!, before: DateTime, limit: Int = 30): [Message!]!`: Recuperación paginada de mensajes en base a un cursor temporal (`before`) para admitir scroll asíncrono e infinito.

- **Mutations (Mutaciones)**:
  - `startConversation(trainerId: ID!): Conversation!`: Inicia un nuevo chat con un entrenador específico.
  - `sendMessage(conversationId: ID!, content: String!): Message!`: Inserta y propaga un nuevo mensaje de texto en una conversación.

- **Subscriptions (Suscripciones)**:
  - `messageAdded(conversationId: ID!): Message!`: Conexión de flujo de datos en tiempo real (vía WebSockets) para suscribirse a nuevos mensajes entrantes dentro de una conversación seleccionada.
